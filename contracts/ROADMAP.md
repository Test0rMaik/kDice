# kDice — 0.45.0 Compilation Fix Plan

Fix the 34 compilation errors against `klever-sc-derive` 0.45.0 by aligning
the contract with the **trait-based contract pattern** (Ogmara reference),
correcting event signatures, and moving `init`/`upgrade` into the contract
trait body.

## Root causes (confirmed)
| # | File | Problem | Fix |
|---|------|---------|-----|
| 1 | `src/events.rs` | `commit_event` / `settle_event` each have **2 data args** (max 1 allowed) | Index `multiplier` / `roll`; keep 1 data arg |
| 2 | `src/settle.rs:45` | `ManagedBuffer::<Self::Api>::from(...)` turbofish (macro parse error) | `ManagedBuffer::from(...)` |
| 3 | `src/settle.rs:56` | `RollRecord::<M>` — `M` undefined | `RollRecord { ... }` (infer `Self::Api`) |
| 4 | `src/upgrade.rs` | `#[endpoint(upgrade)]` — reserved name | Remove the endpoint; `#[upgrade]` lives in the contract trait |
| 5 | `src/lib.rs` | Legacy hand-written `__contract_init` / `__upgrade_init` | Add `#[init]` + `#[upgrade]` to the `KDiceContract` trait body |
| 6 | `meta/Cargo.toml` | `[[bin]] path = "src/bin/sc-meta.rs"` (file is `src/main.rs`) | Point bin at `src/main.rs` |

Cross-module **supertraits are kept** — they are how modules access each
other's `Storage` fields (e.g. `CommitModule` reads `StorageModule` fields).
